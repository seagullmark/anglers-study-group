# 第4章：エラーページとロギング

## 4-1 この章で見ること

公開後のアプリでは、エラーが起きたときの見え方が重要になる。

見ること。

```txt
利用者に見せるエラーページ
開発者が確認するログ
APP_DEBUG=false のときの挙動
Inertia でエラー画面を返す方法
```

今回の対象ブランチ。

```txt
lesson/add-inertia-error-page
```

コミット。

```txt
f17b775 feat: add inertia error page
```

変更されたファイル。

```txt
bootstrap/app.php
resources/js/Pages/Error.vue
resources/js/app.js
```

---

## 4-2 なぜエラーページが必要か

公開環境では、エラーの詳細を利用者に見せない。

例えば、例外のスタックトレース、SQL、パス、設定値などが見えると危険。

公開確認では `.env` を次のようにする。

```env
APP_ENV=staging
APP_DEBUG=false
```

`APP_DEBUG=false` では、利用者には整えたエラー画面を見せる。
開発者はログを見て原因を追う。

```txt
利用者: エラーページを見る
開発者: ログを見る
```

---

## 4-3 `bootstrap/app.php` で例外レスポンスを差し替える

Laravel 11 以降の構成では、例外処理は `bootstrap/app.php` の `withExceptions` に書ける。

今回追加した import。

```php
use Illuminate\Http\Request;
use Inertia\Inertia;
use Symfony\Component\HttpFoundation\Response;
```

追加した処理。

```php
$exceptions->respond(function (Response $response, Throwable $exception, Request $request) {
    if (! app()->environment(['local', 'testing']) && in_array($response->getStatusCode(), [500, 503, 404, 403], true)) {
        return Inertia::render('Error', ['status' => $response->getStatusCode()])
            ->toResponse($request)
            ->setStatusCode($response->getStatusCode());
    }

    if ($response->getStatusCode() === 419) {
        return back()->with([
            'message' => 'ページの有効期限が切れました。もう一度お試しください。',
        ]);
    }

    return $response;
});
```

ここでやっていること。

```txt
local / testing では Laravel のデバッグ画面を使う
staging / production では Inertia の Error ページを返す
対象は 500 / 503 / 404 / 403
419 は前の画面に戻してメッセージを出す
```

---

## 4-4 `local` と `testing` では差し替えない

```php
! app()->environment(['local', 'testing'])
```

ローカル開発では、Laravel の詳しいエラー画面が必要。

そのため、`local` と `testing` では Inertia のエラーページに差し替えない。

公開確認用の `staging` や、本番の `production` でだけ差し替える。

---

## 4-5 対象にしたステータスコード

```php
[500, 503, 404, 403]
```

意味。

```txt
500 Server Error
サーバー側のエラー

503 Service Unavailable
メンテナンス中など

404 Not Found
ページが見つからない

403 Forbidden
権限がない
```

---

## 4-6 419 は別扱い

```php
if ($response->getStatusCode() === 419) {
    return back()->with([
        'message' => 'ページの有効期限が切れました。もう一度お試しください。',
    ]);
}
```

419 は CSRF トークン切れなどで起きる。

通常のエラーページを出すより、前の画面に戻して再操作してもらう方が自然。

## 4-7 Inertia のエラーページ

追加したファイル。

```txt
resources/js/Pages/Error.vue
```

このページは `status` を受け取る。

```js
const props = defineProps({
  status: {
    type: Number,
    required: true
  }
})
```

`status` に応じてタイトルを変える。

```js
const title = computed(() => {
  return {
    503: 'Service Unavailable',
    500: 'Server Error',
    404: 'Not Found',
    403: 'Forbidden'
  }[props.status] || 'Error'
})
```

説明文も `status` に応じて変える。

```js
const description = computed(() => {
  return {
    503: '現在メンテナンス中です。しばらくしてから再度お試しください。',
    500: 'サーバーでエラーが発生しました。',
    404: 'お探しのページは見つかりませんでした。',
    403: 'このページへのアクセス権限がありません。'
  }[props.status] || 'エラーが発生しました。'
})
```

## 4-8 エラーページでは詳細を出さない

エラーページには、原因の詳細を書かない。

出さないもの。

```txt
例外クラス名
スタックトレース
SQL
サーバー上のパス
環境変数
認証情報
```

利用者には状況だけを伝える。

原因はログで確認する。

## 4-9 `resources/js/app.js` の変更

変更前。

```js
import.meta.glob('./Pages/**/**/*.vue')
```

変更後。

```js
import.meta.glob('./Pages/**/*.vue')
```

`resources/js/Pages/Error.vue` は `Pages` 直下にある。

そのため、ページ解決の glob を `./Pages/**/*.vue` にして、直下のページも拾えるようにした。

## 4-11 ロギングを見る

エラーページは利用者向け。

原因調査はログを見る。

Laravel のログ設定はここにある。

```txt
config/logging.php
```

このファイルでは、どこにログを書くか、どのレベル以上を記録するかを決めている。

---

## 4-12 `config/logging.php` の基本

デフォルトのログチャンネル。

```php
'default' => env('LOG_CHANNEL', 'stack'),
```

`.env` ではこうなっている。

```env
LOG_CHANNEL=stack
LOG_STACK=single
LOG_DEPRECATIONS_CHANNEL=null
LOG_LEVEL=debug
```

つまり、Laravel はまず `stack` チャンネルを使う。

`stack` の中身。

```php
'stack' => [
    'driver' => 'stack',
    'channels' => explode(',', (string) env('LOG_STACK', 'single')),
    'ignore_exceptions' => false,
],
```

`LOG_STACK=single` なので、実際には `single` チャンネルに書く。

---

## 4-13 `single` ログ

```php
'single' => [
    'driver' => 'single',
    'path' => storage_path('logs/laravel.log'),
    'level' => env('LOG_LEVEL', 'debug'),
    'replace_placeholders' => true,
],
```

`single` は、1つのログファイルに書く設定。

書き込み先。

```txt
storage/logs/laravel.log
```

確認コマンド。

Laravel のログ。

```bash
tail -n 80 storage/logs/laravel.log
```

`LOG_LEVEL=debug` なので、debug 以上のログが対象になる。

---

## 4-14 `daily` ログ

```php
'daily' => [
    'driver' => 'daily',
    'path' => storage_path('logs/laravel.log'),
    'level' => env('LOG_LEVEL', 'debug'),
    'days' => env('LOG_DAILY_DAYS', 14),
    'replace_placeholders' => true,
],
```

`daily` は日ごとにログファイルを分ける設定。

公開環境では、`single` より `daily` の方が扱いやすい場合がある。

例。

```env
LOG_CHANNEL=daily
LOG_LEVEL=warning
LOG_DAILY_DAYS=14
```

`LOG_DAILY_DAYS=14` は、14日分のログを残す設定。

---

## 4-15 `LOG_LEVEL`

```env
LOG_LEVEL=debug
```

`LOG_LEVEL` は、どの重要度以上のログを記録するかを決める。

主なレベル。

```txt
debug
info
notice
warning
error
critical
alert
emergency
```

公開環境では、全部を細かく出すより、`warning` や `error` 以上にすることもある。

```env
LOG_LEVEL=warning
```

ただし、検証中は原因を追いやすくするために `debug` のまま確認することもある。

---

## 4-16 deprecations

```php
'deprecations' => [
    'channel' => env('LOG_DEPRECATIONS_CHANNEL', 'null'),
    'trace' => env('LOG_DEPRECATIONS_TRACE', false),
],
```

deprecation は、非推奨になった PHP やライブラリ機能の警告。

`.env` ではこうなっている。

```env
LOG_DEPRECATIONS_CHANNEL=null
```

`null` の場合、非推奨警告は捨てる。

将来の Laravel や PHP のメジャーアップデートに備えるなら、ここをログに出す選択もある。

---

## 4-17 その他のログチャンネル

`config/logging.php` には他にもチャンネルがある。

```txt
slack
papertrail
stderr
syslog
errorlog
null
emergency
```

例。

```txt
slack
重大なエラーを Slack に通知する

stderr
Docker やコンテナ環境で標準エラーに出す

syslog / errorlog
サーバーのログ基盤へ流す

null
ログを捨てる

emergency
通常のログ書き込みができないときの退避先
```

今回の構成では、まず `stack -> single -> storage/logs/laravel.log` と理解する。

Slack に通知したい場合は、Slack の Incoming Webhook URL を `.env` に設定する。

例。

```env
LOG_CHANNEL=stack
LOG_STACK=single,slack
LOG_LEVEL=error
LOG_SLACK_WEBHOOK_URL=https://hooks.slack.com/services/xxx/yyy/zzz
LOG_SLACK_USERNAME="Laravel Log"
LOG_SLACK_EMOJI=":boom:"
```

この場合、`single` にファイル出力しつつ、`slack` にも通知する。

`config/logging.php` の `slack` チャンネル。

```php
'slack' => [
    'driver' => 'slack',
    'url' => env('LOG_SLACK_WEBHOOK_URL'),
    'username' => env('LOG_SLACK_USERNAME', 'Laravel Log'),
    'emoji' => env('LOG_SLACK_EMOJI', ':boom:'),
    'level' => env('LOG_LEVEL', 'critical'),
    'replace_placeholders' => true,
],
```

これは自分でコードに組み込む例。

FileMaker API 呼び出しの失敗を検知した場所や、例外を捕まえた `catch` など、必要な箇所に書く。

```php
Log::error('FileMaker API request failed', [
    'layout' => $layout,
    'status' => $status,
]);
```

例。

```php
try {
    // FileMaker API へのリクエスト
} catch (Throwable $e) {
    Log::error('FileMaker API request failed', [
        'message' => $e->getMessage(),
    ]);

    throw $e;
}
```

より重大なものだけ通知したい場合は、`LOG_LEVEL=critical` にする。

```env
LOG_LEVEL=critical
```

```txt

```

## 4-20 この章のポイント

- `APP_DEBUG=false` では詳細なエラーを利用者に見せない。
- Inertia でも専用エラーページを用意できる。
- `bootstrap/app.php` の `withExceptions` でレスポンスを差し替える。
- `local` / `testing` ではデバッグ画面を残す。
- 500 / 503 / 404 / 403 を Inertia の `Error.vue` に渡す。
- 419 は前の画面に戻す。
- `LOG_CHANNEL=stack` と `LOG_STACK=single` で `storage/logs/laravel.log` に書いている。
- エラーの原因は画面ではなくログで追う。
