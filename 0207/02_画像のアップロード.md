# 第2章：画像のアップロード

この章では、  
**Web から FileMaker に画像をアップロードする処理を、実装レベルで整理する。**

単に「アップできた」で終わらせず、  
**入力・保存・後始末まで含めて、事故らない構造を作る**ことが目的。

---

## 2-1 アップロード処理の全体像

アップロード処理は、以下のレイヤに明確に分離している。

| レイヤ | 責務 |
| --- | --- |
| Vue / Inertia | ファイル選択・送信 |
| FormRequest | 入力正規化・バリデーション |
| Controller | 一時保存・画像加工・FileMaker 保存 |
| FileMaker | コンテナへの永続保存 |

> Controller に「全部」書かない。  
> 役割を分けることで、理解していない人が触っても事故らない。

---

## 2-2 ルーティング（登録専用）

### 対象ファイル（ルーティング）

- ルーティング定義：`routes/web.php`

```php
Route::resource('user-photos', UserPhotoController::class)
    ->only(['store']);
```

- アップロードは **POST のみ**
- 一覧・編集・削除は用意しない
- 「画像登録専用エンドポイント」であることを明確にする

---

## 2-3 フロントエンド（Vue / Inertia）

### 対象ファイル（フロントエンド）

- フロントエンド：`resources/js/Pages/Index/Index.vue`

```vue
<form @submit.prevent="submit" enctype="multipart/form-data">
```

- `multipart/form-data` で送信
- `forceFormData: true` を指定し、確実にファイルとして送る

```js
form.post(route('user-photos.store'), {
  forceFormData: true
})
```

### 表示側のポイント

```js
const userThumbnail = computed(() => page.props.auth?.user?.thumbnail ?? null)
```

- 表示は **サーバが返した URL をそのまま使う**
- フロントは FileMaker やセキュリティを一切知らない

---

## 2-4 Request による入力正規化（ContainerRequest）

### 対象ファイル（Request）

- リクエスト：`app/Http/Requests/ContainerRequest.php`

アップロード入力は **必ず FormRequest を通す**。

### なぜ Request に寄せるのか

- バリデーションを Controller に散らさない
- 入力形式の違いを Controller に持ち込まない
- 将来の仕様変更を **一箇所で吸収**する

---

### multipart / base64 を統一する

```php
public function validationData()
```

- base64 で送られてきたデータを
  - デコード
  - tmp ファイルに保存
  - `UploadedFile` として再構築
- Controller 側は **常に `$request->file` を扱えばよい**

> 手書きサイン・Canvas 画像にも対応できる設計。

---

### バリデーションルール

```php
public function rules(): array
{
    return [
        'file' => 'required|mimes:png,jpeg,jpg',
        'file_base64' => 'required_without:file|string',
    ];
}
```

- 形式制約は **必ずここに集約**
- Controller ではチェックしない

---

## 2-5 Controller（UserPhotoController@store）

### 対象ファイル（Controller）

- コントローラ：`app/Http/Controllers/UserPhotoController.php`

### 処理の流れ

1. 認証ユーザー取得
2. private tmp 領域に保存
3. 画像加工（サムネ生成）
4. FileMaker コンテナに保存
5. 旧レコード整理
6. tmp ファイル削除

---

### tmp 保存と画像加工

```php
$path = $file->store('tmp');
$image = ImageManager::gd()->read($file);
$image->cover(128, 128, 'center')->save($fullPath);
```

- public ディスクは使わない
- tmp は **必ず private**
- 後で削除する前提の保存

---

### FileMaker コンテナへの保存

```php
$fmFile = new File($fullPath);
$photo->photo = $fmFile;
$photo->save();
```

- `Illuminate\Http\File` を使用
- FileMaker のコンテナに直接保存
- Web 側で URL を作らない

---

### 1ユーザー1枚を担保

```php
UserPhoto::where('user_id', $user->id)
    ->where('id', '!=', $photo->id)
    ->delete();
```

- データ構造で制約を作る
- アプリロジックに依存しない

---

### tmp ファイルの後始末

```php
Storage::delete($path);
```

- 成功後に必ず削除
- ディスク肥大・情報漏洩を防ぐ

---

## 2-6 storage 設定の前提

### 対象ファイル（storage）

- ディスク設定：`config/filesystems.php`

```php
'local' => [
    'driver' => 'local',
    'root' => storage_path('app/private'),
],
```

- tmp 保存は **private ディスク**
- Web から直接参照されない
- 表示は必ず `/container/{token}` 経由

---

## 第2章のまとめ

> FileMaker への画像アップロードは、  
> **入力を正規化し、保存を最小化し、構造で守る。**

- 入力形式は Request で吸収
- 保存処理は Controller に集中
- 一時ファイルは必ず削除
- FileMaker のコンテナは Web に直接触らせない
