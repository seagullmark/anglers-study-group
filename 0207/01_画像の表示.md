# 第1章：画像の表示

この章では、  
**FileMaker のコンテナ画像を Web から表示するための設計と実装**をまとめる。

ポイントは次の3つ。

- FileMaker のコンテナURLを **直接公開しない**
- Web アプリが **必ず中継して配信**する
- 「分かっていない人が触っても事故らない」構造にする

---

## 1-1 前提と全体像

本資料では、以下を前提とする。

- FileMaker Server：`AuthenticatedStream = 1`
- Web 側：Laravel を利用
- 画像の所有者判定は **FileMaker のリレーション**で行われている

### 基本フロー（表示）

1. ユーザーがログイン
2. Web 画面には **アプリ用の画像URL**だけを渡す
3. `<img src="/container/{token}">` で取得
4. Laravel が FileMaker から画像を取得して返す
5. ブラウザは FileMaker を直接見に行かない

---

## 1-2 /container/{token}

**対象ファイル**

- ルーティング定義：`routes/web.php`

```php
Route::middleware('auth')->group(function () {
    Route::get('/container/{path}', [ContainerController::class, 'getImage'])
        ->name('container');
});
```

### このルートの役割

- FileMaker のコンテナを **直接公開しない**
- 画像表示は必ずこのルートを経由する
- `{path}` には **暗号化されたトークン**が入る

> URLを知っているだけでは画像は取得できない

---

## 1-3 認証の二層構造

**対象ファイル**

- ルーティング：`routes/web.php`
- FileMaker Server 設定：AuthenticatedStream

### Web アプリ側（Laravel）

- `auth` ミドルウェア
- 未ログインユーザーはアクセス不可

### FileMaker Server 側

- `AuthenticatedStream = 1`
- コンテナ取得は **認証セッション前提**

> どちらか一方ではなく **両方で守る**

---

## 1-4 MyUtil（URL変換）

**対象ファイル**

- ユーティリティ：`app/Mylib/MyUtil.php`
- Facade：`app/Facades/MyUtilFacade.php`

```php
class MyUtil
{
    public function getContainerUrl($fm_url)
    {
        if ($fm_url) {
            $path = Crypt::encryptString($fm_url);
            return url('container/' . $path);
        }
        return null;
    }
}
```

### 目的

- FileMaker のコンテナURLをそのままブラウザに出さない
- **アプリ経由のアクセスURL**に変換する

### 実装：`app/Mylib/MyUtil.php`

```php
<?php

namespace App\Mylib;

use Illuminate\Support\Facades\Crypt;

class MyUtil
{
    public function getContainerUrl($fm_url)
    {
        if ($fm_url) {
            $path = Crypt::encryptString($fm_url);
            return url('container/' . $path);
        } else {
            return null;
        }
    }
}
```

### 挙動

- `$fm_url` がある場合  
  - `Crypt::encryptString()` で暗号化  
  - `/container/{暗号化トークン}` を返す
- 空の場合は `null`

> FileMaker の生URLは外に出さない

---

### Facade を用意する

### `app/Facades/MyUtilFacade.php`

```php
<?php

namespace App\Facades;

use Illuminate\Support\Facades\Facade;

class MyUtilFacade extends Facade
{
    protected static function getFacadeAccessor()
    {
        return 'MyUtil';
    }
}
```

### 方針

- Facade は使う
- **エイリアス（`config/app.php`）は使わない**
- 明示的に import する

```php
use App\Facades\MyUtilFacade;

MyUtilFacade::getContainerUrl($fm_url);
```

## 1-5 UserPhoto モデルと $hidden

**対象ファイル**

- モデル：`app/Models/UserPhoto.php`

```php
class UserPhoto extends FMModel
{
    protected $hidden = [
        'photo',
    ];

    protected function thumbnail(): Attribute
    {
        return Attribute::make(
            get: fn ($value) => MyUtilFacade::getContainerUrl($value),
        );
    }
}
```

### なぜ `photo` を `$hidden` に入れるのか

- `photo`（コンテナ）をそのまま返すと  
  **FileMaker の実URLが Web に露出する可能性**がある
- `$hidden` に入れることで  
  JSON / Inertia / API すべてで強制的に除外される

> これは「分かっている人のため」ではなく  
> **分かっていない人と作業しても事故らないための設計**

## 1-6 APP_KEY と暗号化

**対象ファイル**

- 環境変数：`.env`

```env
APP_KEY=base64:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx=
```

- Laravel 全体の暗号化の基点
- `Crypt::encryptString()` / `decryptString()` で使用される

### 保証されること

- このアプリが発行したトークンである
- 改ざんされていない
- 別環境では復号できない

### 保証されないこと

- 誰がアクセスしていいか（認可）
- いつまで有効か（期限）

> 暗号化は秘匿と正当性  
> 認可は別レイヤ

---

## 1-7 パスワードとの違い

**対象ファイル**

- ユーザーモデル：`app/Models/User.php`

- User の password は **ハッシュ**
- 復号できない
- 一致確認のみ

- コンテナURLトークンは **暗号化**
- 後で復号して使う

> 用途がまったく違うので混同しない

## 1-8 ContainerController（表示・検証）

**対象ファイル**

- コントローラ：`app/Http/Controllers/ContainerController.php`

### 作成

```bash
./vendor/bin/sail artisan make:controller ContainerController
```

### 役割

> FileMaker のコンテナを、  
> **安全に検証して配信するプロキシ**

---

### 許可する MIME タイプ

```php
protected $mimes = [
    'pdf'  => 'application/pdf',
    'jpg'  => 'image/jpeg',
    'jpeg' => 'image/jpeg',
    'png'  => 'image/png',
    'gif'  => 'image/gif',
];
```

---

### サイズチェック（DoS・誤配信対策）

- **Content-Length ヘッダ**によるサイズ確認
- **実体サイズ（body 長）**による再確認
- どちらか一方でも上限超過なら即拒否

```php
$maxBytes = 5 * 1024 * 1024; // 5MB
```

> ヘッダ偽装や異常レスポンスによる負荷を防ぐため、二重にチェックする。

---

### ファイルの中身チェック（マジックバイト）

- 拡張子や Content-Type を **信用しない**
- `finfo(FILEINFO_MIME_TYPE)` により **実体バイト列から MIME を判定**

```php
$finfo = new \finfo(FILEINFO_MIME_TYPE);
$detected = $finfo->buffer($body);
```

- JPEG / PNG / GIF / PDF などは  
  先頭バイト（マジックバイト）で形式が判別される

> 見た目が画像でも、中身が HTML / JS のケースを防ぐ。

---

### Content-Type の二重検証

- 上流レスポンスが名乗る Content-Type
- 実体から検出した MIME（マジックバイト）

この2つが一致しない場合は **即拒否**する。

```php
if ($rawContentType !== '' && $rawContentType !== $detected) {
    // mismatch → reject
}
```

---

### SVG を禁止する理由

- 中身は XML（アクティブコンテンツ）
- スクリプト実行が可能
- 外部リソース読み込みが可能
- XSS の踏み台になりやすい

> サーバ側でサニタイズしない限り禁止が安全

---

### nosniff を付ける理由

- Content-Type の誤判定防止
- MIME 偽装による XSS 防止
- 画像配信でも有効

> サーバが指定した型を必ず守らせる安全弁

---

## 第1章のまとめ

> FileMaker の画像表示は、  
> **URLではなく構造で守る。**  
>
> 生コンテナURLは外に出さず、  
> Web アプリが中継し、  
> モデル構造で事故を防ぐ。
