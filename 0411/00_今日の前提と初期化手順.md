# 第0章：今日の前提と初期化手順

この章では、  
**今日の教材を、どの前提で見ていくか** を最初に整理する。

ポイントは次の3つ。

- 最初は **データあり** の状態で画面を見る
- そのあと **作り直しとテストデータ投入** の流れを確認する
- Laravel の考え方を土台にしつつ、FileMaker 向けに自作した command を使う

---

## 0-1 なぜ最初はデータありで始めるのか

今日は最初から、  
**釣行データが入っている状態** を前提に進める。

### この前提にする理由

- 一覧画面がすぐ見える
- 詳細画面がすぐ見える
- `Policy` の説明がしやすい
- `can_edit` の意味が分かりやすい
- `mod_id` を含む編集画面の流れが追いやすい
- `Collection` を使った複数件データの説明がしやすい

空の状態から始めると、
まず「何も出ていない画面」を見ることになる。

それよりも、
**実際にデータが表示されている状態から入った方が、今日のテーマを理解しやすい。**

---

## 0-2 そのあと、作り直しの流れも確認する

画面を見たあとで、
一度テーブルを削除した状態から、

1. schema を作る
2. テストデータを入れる

という流れも確認する。

### ここで見たいこと

- 構造はどう作られるのか
- テストデータはどう入るのか
- Laravel の考え方を、FileMaker でどう置き換えているのか

つまり今日は、
**使う側の画面** と **作る側の初期化手順** の両方を見る回になる。

---

## 0-3 Laravel では本来どうするか

Laravel では、RDB を使うときに
次のような command が基本として用意されている。

```bash
php artisan migrate
php artisan db:seed
```

開発中には、

```bash
php artisan migrate:fresh --seed
```

のように、

- テーブルを作り直す
- 初期データを入れる

という流れもよく使う。

### ここで押さえること

- Laravel には、構造を作る仕組みがある
- Laravel には、テストデータを入れる仕組みがある
- 開発中はこの 2 つを何度も回すことが多い

---

## 0-4 ただし今回の DB は FileMaker

今回は DB が FileMaker なので、
Laravel の通常の migration / seeding を
そのまま使う教材にはしていない。

その代わりに、
このプロジェクトでは
**FileMaker 向けの command を自作している。**

### この教材での考え方

- Laravel の「構造を作る」という考え方はそのまま使う
- Laravel の「テストデータを入れる」という考え方もそのまま使う
- ただし、実行方法は FileMaker に合わせて自作する

> つまり今日は、  
> Laravel の基本思想をそのままにして、  
> 実行部分だけ FileMaker 向けに置き換えている

### なぜ OData を使っているのか

このプロジェクトでは、
FileMaker の schema 作成に **OData** を使っている。

理由は、
OData 側で **構造を定義する操作** ができるから。

SQL でいうと、これは **DDL** に近い。

たとえば次のような操作のイメージになる。

- `CREATE TABLE`
- `ALTER TABLE`
- `CREATE INDEX`

つまり OData は、
データそのものを登録・更新するためというより、  
**テーブルや field の構造を作るため** に使っている。

この教材では、

- schema 作成は OData
- データ投入は Data API

という分け方にしている。

### これも Laravel を知っているからこその発想

この分け方は、
Laravel の migration を知っているから出てくる発想でもある。

Laravel を知っていると、

- 構造を作る処理
- データを入れる処理

を分けて考えるのが自然になる。

その考え方を FileMaker に持ち込むと、

- 構造は OData で作る
- 中身は Data API で入れる

という整理になる。

> つまりこれは、  
> FileMaker を Laravel の考え方で読み直したときに出てくる設計といえる

## 0-5 このプロジェクトで使う command

### schema 用

- `fm:schema:status`
- `fm:schema:apply`

### テストデータ投入用

- `fm:seed:users`
- `fm:seed:fishing-trips`

### 対象ファイル

- `anglers/app/Console/Commands/FmSchemaStatusCommand.php`
- `anglers/app/Console/Commands/FmSchemaApplyCommand.php`
- `anglers/app/Console/Commands/FmSeedUsersCommand.php`
- `anglers/app/Console/Commands/FmSeedFishingTripsCommand.php`

### 役割の分け方

- 構造を作るのが `fm:schema:*`
- 中身を入れるのが `fm:seed:*`

整理すると、

- 構造は schema command
- データ投入は seed command

という分け方になる。

---

## 0-6 schema を作る手順

### 1. まず状態確認

```bash
./vendor/bin/sail artisan fm:schema:status
```

この command では、

- 定義ファイルが読み込まれているか
- どの schema が未実行か
- どの schema が実行済みか

を確認できる。

### 2. 次に `--pretend`

```bash
./vendor/bin/sail artisan fm:schema:apply --pretend
```

これは、
**実際には変更せず、何を実行する予定かだけ確認する** command。

いきなり本実行せず、
まずここで内容を見る。

### 3. 問題なければ本実行

```bash
./vendor/bin/sail artisan fm:schema:apply
```

これで FileMaker 側に schema を適用する。

### 今回の対象

- `fishing_trips`
- `fishing_trip_photos`

定義ファイルは次。

- `anglers/database/filemaker-schema/2026_04_10_000001_create_fishing_trip_tables.php`

---

## 0-7 テストデータを入れる手順

### 1. ユーザーを入れる

```bash
./vendor/bin/sail artisan fm:seed:users
```

必要なら件数や password を変えられる。

```bash
./vendor/bin/sail artisan fm:seed:users --count=3 --password=laravel
```

### 2. 釣行を入れる

```bash
./vendor/bin/sail artisan fm:seed:fishing-trips
```

必要なら件数や画像枚数も変えられる。

```bash
./vendor/bin/sail artisan fm:seed:fishing-trips --count=6 --photos=1
```

### なぜこの順か

- 釣行はユーザーに紐づく
- 先にユーザーが必要
- そのあとで釣行と画像を入れる

---

## 0-8 ここで知っておきたいこと

Laravel では本来、
`migrate` や `seed` のような考え方が最初から用意されている。

今回は FileMaker なので、
その考え方をそのまま使いながら、
**実行部分だけ自作 command に置き換えている。**

つまりこの教材で見ているのは、

- Laravel の考え方を捨てた別物

ではなく、

- Laravel の考え方を FileMaker に合わせて実装したもの

という理解でよい。
